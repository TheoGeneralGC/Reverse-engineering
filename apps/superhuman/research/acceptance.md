## REA execution pattern

Use the installed release's actual tool schemas. REA 6.8.0 CLI was checked for
`capture-browser-scenario` and `compare-web-captures`. Repository-main docs also
describe `validate-browser-scenario`, but that command is absent from this pinned
release; do not treat global help output as successful scenario validation.

For an original capture, discover the target with `list_browser_targets`, then
use connect mode with its actual target ID. Connect mode first navigates to
`start_url`: ensure no existing unsaved user draft is open. Set
`environment.service_workers` to `allow` for an app whose existing registrations
require it; the default blocking policy can reject such a connected target.
Never overlap a passive capture and an active scenario on the same page.

Below is a template for a replica fixture smoke capture, not a tested current UI
selector. Replace `data-testid` and readiness condition with the implemented
fixture screen. Use identical step IDs for corresponding original/replica runs.

```json
{
  "browser": {
    "mode": "launch",
    "executable_path": "/Applications/Google Chrome.app/Contents/MacOS/Google Chrome"
  },
  "start_url": { "url": "http://127.0.0.1:5173" },
  "environment": {
    "viewport": { "width": 1440, "height": 900, "device_scale_factor": 1 },
    "locale": "en-US",
    "timezone": "America/Los_Angeles",
    "color_scheme": "dark",
    "reduced_motion": "reduce",
    "service_workers": "allow"
  },
  "actions": [
    {
      "step_id": "inbox-ready",
      "action": "wait_for",
      "locator": { "kind": "css", "selector": "[data-testid='inbox'][data-state='ready']" },
      "state": "visible",
      "timeout_ms": 10000
    }
  ],
  "capture": { "at_end": ["screenshot", "dom", "accessibility", "url"] }
}
```

Run saved JSON with `npm run rea -- capture-browser-scenario <scenario.json>
--json`, directing output to an ignored private capture file. Compare matched
captures with `npm run rea -- compare-web-captures <before.json> <after.json>
--json`. Read coverage and comparison findings; a command exit code alone does
not establish equality. Normalize only declared literal differences such as
the reference/replica origin and synthetic IDs. Do not normalize away content,
layout, ordering, missing controls or failed state changes.

Visual tolerances must be agreed from actual capture noise. Start by reporting
pixel/geometry differences and review them; do not invent a permissive threshold
and label the interface one-to-one. Re-run changed scenarios after fixes, plus
the integration path affected by shared code. Keep inaccessible cases open.
