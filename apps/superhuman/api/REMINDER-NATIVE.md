# Private reminder native vertical prototype

This private factory successor is rooted in reviewed author fix 97761191 of the
V4/native prototype. It mounts only when createApp receives explicit native
configuration; the existing CLI, Google importer and UI remain unmounted. Every
browser capability stays false. Ordinary schedule/cancel/Undo POSTs remain409;
explicit context-read and keyed check-return intents have separate guarded APIs. No real provider proof, automatic Follow-ups, model call,
new OAuth scope, mail Send or Main action is claimed.

The ordinary injected path works: explicit fresh context → keyed local schedule
→ one guarded thread.modify archive → exact native absence-of-INBOX observation
→ due condition/read → one own-mailbox messages.insert → exact message/thread
observation → atomic returned occurrence/outbox/date clear/Thread update. IMPORTANT
is an explicit fixture policy, defaultfalse. The mailbox insert mechanism is a
replica design supported by Google's documented gmail.modify scope, not recovered
original transport. Original service-email creation remains an observation with
unknown server transport/cause.

## Single authority and source context

The isolated author-validation correction retains complete raw From header
values in server-only native plan facts before the generic import Person parser
can collapse them. Conditional assessment requires exactly one strictly parsed
author: multiple, missing, malformed or duplicate From evidence cannot establish
self-only absence. One configured alias and a quoted display-name comma remain
supported. Captured raw author facts are immutable source evidence for both
conditions; new ambiguous authors block only conditional evaluation. This is a
bounded replica safety correction, not recovered original author policy.

`ReminderRuntime` owns the injected GoogleProvider and ReminderService, with
explicit adoption and synthetic/current server signing material. It never reads
a file or process env. Constructor starts no native work. Fresh exact native
thread and field-masked SendAs observations establish short-lived context; cached
Thread alone cannot. Account incarnation, selected provider thread and current
MAIL grant are fenced before/after awaits and adjacent to the native issue.
Primary From=soleTo is independently validated; all configured literal aliases
are used for self-exclusion without dot/plus guessing. No Claude profile is needed.

The agreed pure classifier is imported exact from Root-cleared V2e30bc31c.
Full raw chronology stays in Thread messages/native observations. Its visible
and last-real selectors exclude coherent original-trigger candidates and proved
own carriers. Indeterminate records never establish human absence. A newly seen
untrusted original candidate blocks conditional assessment; it is not a human
reply or canonical returned occurrence. New ordinary external From evidence
suppresses if-no-reply; regardless may return while its captured source remains
valid. This is not proof of human identity or original complete reply policy.

Trusted context exclusion IDs/classification hash are server-only DI fields,
not client-selectable JSON. Source body/hash and complete captured message set
are checked; real new messages are preserved. Same read/star metadata does not
change source facts. The context path is an explicit native action, not a GET
route. Service view/recovery remains zero-native/zero-write.

## Dedicated transport and durable issue

`google-reminder-command.ts` admits only exact-thread GET, archive, one insert,
exact prepared RFC-ID lookup and exact message GET. Commands are cloned and
prepared before awaits. The dedicated GoogleProvider method uses existing tokens
and read pacing, then repeats the trusted guard adjacent to its single fetch.
It has a fixed deadline/response budget and no automatic write or read retry.
The existing fourth Send, fifth SendAs and leased sync/default request bodies
are reverse-byte-exact; the new method does not repurpose them.

The existing seven reminder tables hold immutable prepared/issued/ACK/observed
journal records. Their fixed scope, generation, request hash, previous digest
and plan are independently committed by slot events. One generation/purpose has
one prepared plan; issue is an irreversible once-only transaction. Two owners
cannot issue twice. Credentials and model waits never occur inside SQL.

The carrier is app-authored escaped plain+HTML with no attachment/remote asset.
From/To are the verified primary, with honest Replica Reminders display name.
Subject and source In-Reply-To/References/thread are fixed. Prepared RFC bytes,
requested Message-ID and HMAC tuple are retained before issue. No vendor domain,
SMTP sender, x-superhuman header, body or HTML is spoofed. Key bytes are copied
in memory/zeroed onStop and never hashed into public history or persisted.

Bare own/original headers are not authority. Positive carrier recognition needs
exact provider message/thread, the issued independent local plan and expected
MIME/headers, constant-time MAC check, and the classifier's exact owned witness
binding. Duplicate own headers remain indeterminate, including for regardless.
The local return/outbox references that observed proof. The last-real source
anchor remains the received source rather than the system carrier.

## Unknown and publication

A timeout/lostACK leaves issued unknown. Restart never repeats that insert.
Explicit internal reconciliation uses only the exact prepared RFC-ID query plus
bounded exact GETs. Empty/duplicate/partial matches remainunknown; no second write.
Archive lostACK similarly uses exact read-only observation and never repeats
modify. Same-key schedule recovery is historical, zero-native and never reapplies
placement. A late cancellation retains old ACK history without publishing to a
replacement generation.

Only a positively observed current generation can atomically publish one return,
account ordinal, pending outbox and cleared local date. Thread source updates
retain concurrent read/star fields. Later hook/outbox failure rolls publication
back; explicit GET recovery may finish without resend. Return/outbox columns,
hashes, occurrence digest and observed journal are cross-bound to slot history.
No consumer uses that outbox yet and it does not admit a model.

## Factory, explicit APIs and shutdown

`createApp({reminderNative:{key,keyId,important?,automatic?,googleFetch?}})`
requires exactly 32 injected key bytes and a bounded signer ID before Store
construction. Configuration has no file, environment, random-key or default-key
fallback. Root's future private configuration helper must supply the same key
and keyId across restarts; arbitrary rotation cannot reconcile existing plans.
The runtime copies the bytes and zeroes its copy on Stop. No key or key hash is
serialized into a public response. `reminderFoundation` and `reminderNative`
are mutually exclusive. Explicit shared Google fetch injection must agree with
Auto Drafts injection when both are present; default Send/SendAs/sync request
implementations are unchanged.

Automatic scheduling defaults false and runJobs:false never starts it. Explicit
automatic configuration owns one timer, scans at most32 scheduled slots per
tick, and calls the guarded runtime outside SQL. An unconfirmed archive blocks
automatic work without background native reads. Issued unknown and prepared
insert slots are never replayed. Close synchronously stops native issue/cancels
the timer, then waits all owned work, HTTP intents and ticks before Store.close.
A queued callback that arrives after Stop is inert. No model or Follow-up is
called by this scheduler or any reminder SQL transaction.

The following APIs are prepared for server integration; they do not enable UI
capabilities or establish original parity:

- GET `/api/threads/:threadId/reminder?accountId=...` remains local view only.
- GET `/api/threads/:threadId/reminder/native?accountId=...` adds only opaque
  attempt refs/purposes and issued/observed booleans. It returns no raw headers,
  native plan, provider IDs, exclusions, author facts or HMAC witness.
- POST `/api/reminder-contexts` accepts exactly accountId/accountVersion/threadId.
  It performs explicit native identity+thread reads and establishes authoritative
  short-lived server context; client classifications/exclusions/proofs refuse.
- POST `/api/reminder-actions` accepts only canonical `check-return` requests. It
  CAS-binds the current slot/ref/generation and exact known issued wake/archive
  attempt, commits immutable unchanged-snapshot acceptance, then runs only the
  existing bounded provider GET reconciliation. No archive/insert is issued.
- GET `/api/reminder-actions/by-request/:key?accountId=...&accountVersion=...`
  reads original acceptance and optional final result, validates the complete
  reminder/native/return lineage, and starts zero native work. Same-key POST
  recovery also never repeats a pending/completed check. A new explicit key is
  required for a later read-only check after an incomplete/unknown result.

Three additive tables store check requests, independent immutable proof events
and one immutable result. They cross-bind the canonical request/receipt, prior
slot head, final snapshot/head and result. The existing seven reminder tables
retain their schema; a new private journal stage records lease ownership.
No existing keyed receipt, source anchor, return or outbox is rewritten.

## Prepared but not issued continuation

`owner.continuePrepared` is server-only and explicit; no GET, UI or automatic
tick invokes it. It independently checks the coherent slot/event/native proof
lineage for exactly one original plan with **no issued/ACK/observed stage**. An
other owner's unexpired lease refuses with zero native work. An expired lease
can transfer only after fresh native reads, same current account incarnation,
slot revision, reminder/generation/anchor/source facts, grant, signer and current
conditional assessment. The transfer atomically appends an immutable owner/lease
record linked to the old plan/proof; it does not change the plan or RFC bytes.
The old owner is fenced by the latest lease immediately before issue. Current
CAS or source changes refuse/hold; cancelled generations stay historical.

Any issued lineage remains unknown/no-replay regardless of expiry. Reconciliation
is the explicit GET-only check path. This is not a Gmail atomic source/write CAS;
an outside change between bounded native preflight and issue remains a stated
race. Full importer/H7/UI adoption and actual owned-provider proof remain open.
