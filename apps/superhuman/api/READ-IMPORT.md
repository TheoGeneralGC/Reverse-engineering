Only an explicit keyed account refresh requests collector events. Constructors, ordinary local GETs, account switches, autosave, Send/Undo and model calls perform no read import. Every request uses a narrow event-GET-only child reader with isolated abort; it cannot register/arm/confirm or request a pixel, Google or a model. Parent shutdown closes all readers. The separate server-only runtime loader remains root-owned and is not implemented here.

The whole selected-account/current-configuration acknowledged+collector-confirmed delivery set is verified through immutable acceptance, positive confirmation and primary Sent proofs. A derived indexed projection/count is updated with the delivery transaction; migration only validates already-owned delivery records. It does not enroll legacy mail/drafts. No eligible set or over10,000 bindings is an explicit unavailable state, never a subset sample.

A new refresh atomically stores a scoped immutable receipt and accepted snapshot before asynchronous GET work. Exact replay and by-key GET return historical acceptance/result and never resume. Accepted account revision advances by1; terminal result advances beyond acceptance. Superseding, close, preference/configuration changes, elapsed budget or changed proof basis fence subsequent reads and commit. Live owners are not reclaimed merely by construction. Abandoned dead-owner requests become interrupted locally; no startup retry occurs.

Multi-page through/revision identity is frozen. Duplicates, unknown registration/ACK, stale pages and incomplete/limited reads fail the whole import. Complete snapshot, new immutable events/messages, head and terminal result commit together. The published head is additionally matched against the latest append-only head commitment. Separate retained-message/event commitments detect missing rows and bind their immutable identity/bytes before a local view can report surviving counts or return rows. A prototype cache without these commitments is not silently blessed or backfilled from mutable data; it fails closed. No prior RI prototype is deployed. Failure preserves the old head/history. Cumulative throttling is the maximum sampled account counter from that import, never summed across pages or treated as per-message loss.
